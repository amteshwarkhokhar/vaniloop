| 2026-10-09 | `qty_probing` (bot never asks quantity) is NonFatal, not Fatal. | IndiaMART's human audit grades Qty Probe mostly Non-Fatal and fails it only when quantity is defined on the category, which a transcript cannot show. | 2026-10-09 | `qty_missed` is Fatal only when the buyer never repeats the quantity after a re-ask. A re-ask the buyer answers is NonFatal. | All 7 Fatal cases on 103 calls were one re-ask after a mishear, then the right value. Official Fatal = wrong or missing buyer info in the lead. |
| 2026-10-09 | Calibration re-scores saved ledgers with `pipeline regrade` (no LLM call). The pre-calibration audit is kept as `runs/audits_v1_before_calibration.jsonl`. | Rule changes are free to test. Hand-grade agreement can be reported before and after. |
| 2026-10-09 | Ship gate = exact one-sided stratified permutation test (conditional CMH / stratified Fisher), α 0.05, K old + K new replays per call; demo design n=5, K=3. Replaces the old-only noise floor. | Codex showed the old-only floor ships a non-fix ~14% of the time. Fable: exact test is deterministic; n=5,K=3 gives 94% power for 0.8→0.2 and ~0.2% false ships. |
| 2026-10-09 | Guard Fatal is re-checked once under NEW and OLD; it rejects only if NEW fails again and OLD does not. A NEW Fatal on any parameter of a target call rejects. | One guard Fatal alone gives ~40% false rejects at a 5% background Fatal rate over 10 guards. |
| 2026-10-09 | Transcribe our own audio with Gemini (src/vaniloop/transcribe.py) and keep per-turn tone, overlap, unclear audio and bot-misheard. | Pre-built pipelines are disqualified. Audio signals fix the missed irritation on call 282. ~$0.003 per call. |
| 2026-10-09 | `category_isq` splits question level from option level: `question_fits_product` False is Fatal, `fits_confirmed_product` False under a fitting question is NonFatal, and an old ledger without the new label is Unknown. | The human rubric grades a wrong spec question F and a wrong option NF. A second check of the 5 Fatals agreed with 2 and would downgrade 3 (right question, wrong options). |
| 2026-10-09 | Fix patches the clean main prompt: `prompt.load()` removes U+FEFF and Markdown escapes, keeps every line number and cuts to lines 1-1722. | The model copies visible text, so raw anchors missed. Lines 1723+ are variants that 100 of 103 audited calls never use. |
| 2026-10-09 | Proof replays use the Gemini-played bot on the clean main prompt (`replay.py`), not the Sarvam replica. | The replica cannot take per-call variables and its counters stay frozen (`ideation/07_sarvam_replica.md`). |
| 2026-10-09 | Replays are as noisy as the forked call: `unclear_rate` is the share of post-fork user turns flagged `audio_unclear` or followed by a `bot_misheard` bot turn (cap 0.8). Each generated buyer turn is unclear with that chance, seeded by `seed:call_id:idx`. The bot sees `[unclear audio]`, the record keeps the real text. | The first gate run (cause_looping) rejected the patch with lift 0: the old prompt looped in 0 of 15 text replays because every buyer line arrived clean. Real loops start when the bot does not hear the buyer (12 of 20 looping calls carry such a flag near the onset). |
| 2026-10-09 | Replays render the VANI Jinja prompt per call (`render.py`: variables inferred from the ledger, undefined renders empty, sandboxed) and `BOT_FORMAT` says a seller handoff or a closing line ends the call (`end_call` true). Old and new prompts get the same treatment, and the old/new label still compares the unrendered texts. | The qty_probing gate rejected a patch (old 3/15, new 7/15 fail) on two replay artifacts: the bot got all 114 Jinja tags with every branch and took the live-seller branch on a call with no live seller, and with no transfer tool it never ended after a handoff and irritated the simulated buyer. |
| 2026-10-09 | `pipeline refix` writes a second patch from the gate's replay evidence. `patches.json` keeps the rejected patch in `history` and the new patch has `attempt` + 1. `prove --attempt N` refuses a patch of another attempt. | A rejected patch carries evidence (gate numbers, still-failing NEW replays) that a blind second fix would waste. The attempt number keeps a gate row tied to one patch. |
| 2026-10-09 | `prove` picks targets a text replay can judge: it drops a call when the patch renders the same old and new prompt for it (stop below 3 targets: "patch does not reach this cause's calls"), drops a call whose fork turn or the user turn before it is `bot_misheard` or `audio_unclear` (next seeded candidate fills in), forks `product_change` at the first bot turn after `product_changed_at_turn` in every scope, and appends a "Call values" JSON block (product, specs with offered options, units asked) to every rendered prompt. | The fidelity audit (9 Oct) found NEW replays that were OLD cache hits, 4 of 5 causes tested on mishearings the replay cannot reproduce, and a fork after the change it should test. Rendering only switches branches, so the bot never saw the call's values. |
| 2026-10-09 | The gate judges only findings that start at or after the replay's fork. A target replay fails the cause only with a Fatal/NonFatal cause finding at or after the fork; a pre-fork or NotApplicable cause finding makes the trial unresolved. The NEW-Fatal reject counts only post-fork Fatal findings, on any parameter. If OLD fails 0 times, the decision is `inconclusive` ("replay did not reproduce the fault") before the lift rule. | The fork copies the turns before it verbatim into every replay under both prompts, so a patch cannot change them (call 439 forced a reject from a Fatal at turn 8). OLD at 0/15 on looping, qty_missed and category_isq meant the replay did not show the fault, not that the patch failed. Issue #63. |
| 2026-10-09 | `pipeline golden build` freezes up to 150 hand-graded calls into `runs/golden/v<N>.json` (sha256, never overwritten), about 60% human Pass, spread over scope, variant and cause. `golden agreement` scores the audit per rule with Cohen's kappa: below kappa 0.6 or n 10 a rule is `advisory` and may not block or pass a fix. `fix.py` never reads `runs/golden/` (a test enforces it). | A fix tuned on the owner's answers would make the gate meaningless, and a rule the audit grades unlike the owner must not decide a fix. A hand grade holds a failing-parameter list, so the human label per rule is binary (fail or no fault). Issue #75. |
